# 设计说明

这份文件记录「为什么这么做」，避免后来的人（包括未来的自己）把已经想清楚的事重做一遍。

## 1. 流程：三步，每步都看得见依据

```
更新数据  →  预览（可分析性检查）  →  开始 AI 分析（花钱，需确认）
                                        ↓
                              3 组选题方向 + 关键词
                                        ↓
                     第一轮：手绘 7/30 天曲线 → AI 深挖 3 个新关键词
                                        ↓
                     第二轮：再画一次 → 联网核实 → 事件去重 → ≤3 个标题
```

前两步免费。第 3 步开始才调模型，按钮有二次确认。

## 2. 为什么「两轮」而不是一轮

一轮只能回答「什么方向热」，回答不了「哪个具体事件值得写」。第二轮把趋势收敛到**可核实的事件**上：先按关键词搜新闻、抓正文，再让模型在正文范围内出标题，禁止用旧知识编新闻。

这也是为什么必须外接搜索：DeepSeek 的 API 本身没有联网能力，提示词里写「请联网」是无效的。

## 3. 7 天 / 30 天是「一条曲线、两个视角」

手绘数据按**绝对时间戳**存一份，两张图只是时间窗口不同：画了 7 天，30 天图自动把这段压缩显示在右侧 1/7 处；不重复画、不存两份。撤销 / 清空 / 完成 / 无数据都是对整条曲线操作，两张图同步。

时间轴按打开当天刷新；超出范围的旧点只提示，不伪装成当天数据。

**手绘数值是用户目测估算**，界面和喂给模型的材料里都写明「不是微信指数官方数据」。这条不能省——省了模型就会把估算值当权威指标来论证。

## 4. 成本与执行模型

- 提交才收费，按钮需二次确认；
- 分析跑在后台线程，关掉浏览器标签页也会继续；
- 进度用轮询读，不依赖长连接；
- 第二轮输出上限设 8000 token，因为思考型模型的 reasoning 会把 4000 吃干净，正文还没开始就截断了。

## 5. 去重按「事件」，不按标题文字

同一个事件可以从不同角度写多个标题，所以**同一次生成内**允许同事件多角度；但**跨批次**视为已推荐，必须挡住。

判定按顺序两路：

1. 事件标识（`地点+主体+日期`）规范化后相等 → 判重；
2. 否则比事件要点的相似度，两路任一命中即判重：
   - 整句字符序列相似 ≥ 0.50；
   - 剥离「启动/发布/通报/典型案例/活动」这类**不携带事件身份**的套话后再比，相似 ≥ 0.45。

阈值是量出来的，不是拍的：在 3 条真实事件上构造 12 条「同事件换说法」+ 12 条「同地区不同事件」做标注集，旧口径（bigram Jaccard 0.72）只召回 3/12，等于去重失效；现口径召回 10/12 且零误伤。取舍是**宁可少给一个选题，也不要重复推荐同一事件**。

套话必须剥：不剥的话「重庆启动植树造林活动」和「重庆启动野生动物保护月」会因为共同的「重庆启动…活动」被误判成同一事件。

`test_wechat_index_dedup.py` 把这个口径钉住了，改阈值前先跑它。

## 6. 账号定位

只分析自己、不参考对标；每两个完整周期更新一次；不满两个周期不触发；失败沿用旧定位、不阻断分析。定位会并进后续的选题提示词。

## 7. 联调沙盒与正式数据严格分离

沙盒期（教程用的演示周期）和正式周期的数据**物理隔离**：

```
微信指数验证/<账号>/<周期>/                   正式
微信指数验证/_AI联调沙盒/<账号>/<周期>/        沙盒
选题去重库/<账号>.xlsx                        正式
选题去重库/_AI联调沙盒/<账号>.xlsx             沙盒
```

`task.json` 里有 `sandbox` 字段决定写回位置。意义在于：演示数据绝不能挡掉真实选题的推荐。

## 8. 已知限制

- 手绘依赖人的目测，主观性强；
- 搜索服务返回质量直接决定第二轮质量，搜不到就只能给 0～2 个标题（设计上允许，宁缺毋滥）；
- 去重是启发式的，边界情况（同地同主体、不同时间的新进展）可能被误判成重复；
- 只支持 Windows 启动脚本（Python 主体跨平台）。
